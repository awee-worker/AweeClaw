# Frontend Design Guidelines

创建生产级前端界面，参考行业顶级设计规范。

## 核心设计原则

### 1. 设计风格定位
根据项目类型选择合适的设计风格：

| 项目类型 | 推荐风格 | 代表网站 |
|---------|---------|---------|
| AI/LLM产品 | 深色主题、渐变强调色、终端感 | Claude, Cursor, Vercel |
| 开发者工具 | 深色IDE风格、代码感 | Raycast, Warp, Expo |
| 金融/支付 | 信任感、精确、渐变紫/绿 | Stripe, Revolut, Coinbase |
| 电商/零售 | 全幅摄影、简洁有力 | Shopify, Nike, Apple |
| 生产力工具 | 极简、精确、紫/线性风格 | Linear, Notion, Cal.com |
| 媒体/消费 | 品牌色、大胆排版 | Spotify, Spotify |

### 2. 设计信条
- **宁缺毋滥**：减少元素，提升体验
- **细节决定品质**：关注间距、阴影、微交互
- **一致性**：统一的间距、颜色、字体
- **层次分明**：视觉层级清晰，信息有序

## 文件结构

```
project/
├── index.html          # 入口文件（必须）
├── about.html          # 其他页面
├── css/
│   └── main.css       # 样式文件
├── js/
│   └── main.js        # 脚本文件
└── images/            # 图片目录
```

## 关键要求
- **分离CSS/JS**：不要内联样式和脚本
- **完整CSS**：确保每个页面有所有需要的样式
- **相对路径**：使用 `css/main.css`，不要用绝对路径
- **禁止 file://**：浏览器不支持本地文件协议

## ⚠️ 文件创建工具使用规范（极其重要！）

**创建文件时必须使用 `write_file` 工具，且必须同时提供 `path` 和 `content` 两个参数！**

### 正确的工具调用格式

```
write_file(
  path="css/main.css",
  content="/* CSS内容 */"
)
```

### ❌ 常见错误（会导致 <empty path> 错误）

1. **path 参数缺失或为空**：
   - ❌ `write_file(content="/* CSS内容 */")` — 缺少 path
   - ❌ `write_file(path="", content="/* CSS内容 */")` — path 为空
   - ✅ `write_file(path="css/main.css", content="/* CSS内容 */")` — 正确

2. **CSS 内容中的双引号未转义**：
   - ❌ `content="body { font-family: "Arial"; }"` — 双引号冲突
   - ✅ `content="body { font-family: 'Arial'; }"` — CSS 中使用单引号
   - ✅ `content="body { font-family: \"Arial\"; }"` — 正确转义

3. **CSS 内容过长导致参数解析失败**：
   - 当 CSS 文件超过 3000 行时，建议拆分为多个 CSS 文件
   - 使用 `@import` 在主 CSS 文件中引入子文件

### CSS 文件创建策略

**小型项目（CSS < 500 行）**：直接使用 `write_file` 一次性创建

**中型项目（CSS 500-2000 行）**：拆分为多个 CSS 文件
```
css/
├── main.css          # 主入口，@import 其他文件
├── reset.css         # CSS Reset
├── variables.css     # CSS 变量
├── components.css    # 组件样式
└── pages.css         # 页面特定样式
```

**大型项目（CSS > 2000 行）**：按功能模块拆分
```
css/
├── main.css          # 主入口
├── base/
│   ├── reset.css     # CSS Reset
│   └── variables.css # CSS 变量
├── components/
│   ├── buttons.css   # 按钮样式
│   ├── cards.css     # 卡片样式
│   └── forms.css     # 表单样式
└── pages/
    ├── home.css      # 首页样式
    └── about.css     # 关于页样式
```

### CSS 中使用 @import 拆分文件

```css
/* main.css - 主入口文件 */
@import 'reset.css';
@import 'variables.css';
@import 'components.css';
@import 'pages.css';
```

**注意**：每个 CSS 子文件仍然需要独立完整，不要依赖其他文件的未定义变量。

### 创建文件时的关键注意事项

1. **path 必须是相对于工作区根目录的路径**：如 `css/main.css`、`js/main.js`
2. **content 中的双引号必须转义**：CSS 中尽量使用单引号
3. **先创建目录再创建文件**：如果目录不存在，先使用 `create_file_or_folder` 创建目录
4. **每个文件独立创建**：不要在一个 `write_file` 调用中创建多个文件

## ⚠️ HTML基础模板（强制使用）

**每个HTML文件必须包含以下基础结构，缺少任何一项都会导致样式混乱！**

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta http-equiv="X-UA-Compatible" content="IE=edge">
  <title>页面标题</title>

  <!-- 字体CDN（根据项目选择，不要全部加载） -->
  <link href="https://fonts.font.im/css2?family=Noto+Sans+SC:wght@400;500;700&display=swap" rel="stylesheet">

  <!-- 图标CDN（按需选择一个） -->
  <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/css/all.min.css">

  <!-- CSS框架CDN（⚠️ 只能选一个！Tailwind和Bootstrap不能同时使用） -->
  <!-- 选项A: Tailwind CSS -->
  <!-- <script src="https://cdn.tailwindcss.com"></script> -->
  <!-- 选项B: Bootstrap 5 -->
  <!-- <link href="https://cdnjs.cloudflare.com/ajax/libs/bootstrap/5.3.0/css/bootstrap.min.css" rel="stylesheet"> -->

  <!-- 自定义样式（必须在框架CSS之后加载，确保优先级） -->
  <link rel="stylesheet" href="css/main.css">
</head>
<body>
  <!-- 页面内容 -->

  <!-- JS文件放在body末尾 -->
  <script src="js/main.js"></script>
</body>
</html>
```

### HTML基础结构说明（必须理解）

| 元素 | 作用 | 缺失后果 |
|------|------|---------|
| `<!DOCTYPE html>` | 声明HTML5文档类型 | 浏览器进入怪异模式，布局完全错乱 |
| `<html lang="zh-CN">` | 声明页面语言 | 屏幕阅读器发音错误，SEO受损 |
| `<meta charset="UTF-8">` | 声明字符编码 | 中文显示为乱码□□□ |
| `<meta name="viewport">` | 控制移动端视口 | 手机上页面缩放异常，文字极小 |
| `<meta http-equiv="X-UA-Compatible">` | IE兼容模式 | 旧版IE使用兼容视图渲染 |

### `<head>` 中元素加载顺序（必须遵守）

```
1. <meta charset>          ← 必须第一个，确保后续内容正确解析
2. <meta viewport>         ← 必须第二个，控制视口
3. <meta http-equiv>       ← IE兼容
4. <title>                 ← 页面标题
5. 字体CDN <link>          ← 字体尽早加载，避免FOUT
6. 图标CDN <link>          ← 图标字体
7. CSS框架CDN <link>       ← 框架样式
8. 自定义CSS <link>        ← 自定义样式必须在框架之后
9. <script> (仅Tailwind)   ← Tailwind需要script标签
```

## CSS Reset（强制包含）

**每个CSS文件开头必须包含以下Reset代码，否则不同浏览器渲染不一致！**

```css
/* ===== CSS Reset（必须放在CSS文件最开头）===== */
*,
*::before,
*::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

html {
  -webkit-text-size-adjust: 100%;
  -moz-text-size-adjust: 100%;
  text-size-adjust: 100%;
  scroll-behavior: smooth;
}

body {
  min-height: 100vh;
  line-height: 1.5;
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}

img, picture, video, canvas, svg {
  display: block;
  max-width: 100%;
}

input, button, textarea, select {
  font: inherit;
}

p, h1, h2, h3, h4, h5, h6 {
  overflow-wrap: break-word;
}

a {
  color: inherit;
  text-decoration: none;
}

ul, ol {
  list-style: none;
}
```

### 为什么CSS Reset是必须的？

| 问题 | 无Reset的表现 | 有Reset的表现 |
|------|-------------|-------------|
| `box-sizing` | padding/border撑破布局 | 尺寸计算准确 |
| 默认margin | 浏览器给body加8px margin | 从0开始，完全可控 |
| 标题大小 | h1-h6默认大小差异巨大 | 统一重置，自定义控制 |
| 列表样式 | ul/ol有默认缩进和圆点 | 干净无样式，按需添加 |
| 图片间隙 | 图片底部有3-5px间隙 | 图片紧密排列 |

## CSS变量系统（强制定义）

**所有组件样式依赖CSS变量，必须在CSS文件中先定义变量再使用组件！**

```css
:root {
  /* 必须选择一个配色方案完整定义，不能只定义部分变量 */

  /* 示例：暗色高级方案（AI/开发者工具） */
  --primary: #10B981;
  --primary-hover: #34D399;
  --surface: #0A0A0A;
  --surface-elevated: #171717;
  --surface-overlay: #262626;
  --text: #FAFAFA;
  --text-muted: #A3A3A3;
  --border: #2E2E2E;
  --accent: #10B981;

  /* 功能色 */
  --success: #10B981;
  --warning: #F59E0B;
  --error: #EF4444;
  --info: #3B82F6;

  /* 间距 */
  --space-1: 0.25rem;
  --space-2: 0.5rem;
  --space-3: 0.75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
  --space-12: 3rem;
  --space-16: 4rem;

  /* 圆角 */
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;
  --radius-xl: 16px;

  /* 阴影 */
  --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.05);
  --shadow-md: 0 4px 6px -1px rgba(0, 0, 0, 0.1);
  --shadow-lg: 0 10px 15px -3px rgba(0, 0, 0, 0.1);

  /* 动画 */
  --duration-fast: 150ms;
  --duration-normal: 300ms;
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
}
```

**⚠️ 关键规则：**
- 使用任何组件样式前，必须确保 `:root` 中定义了该组件需要的所有变量
- 如果组件用了 `var(--primary)` 但 `:root` 中没有 `--primary`，样式会静默失败
- 每个项目只选一个配色方案，不要混搭

### 常用框架CDN

**⚠️ 严重警告：Tailwind CSS 和 Bootstrap 5 不能同时使用！只能选择其中一个！**

两者同时加载会导致：
- CSS Reset 冲突（Tailwind 的 Preflight 和 Bootstrap 的 Reboot 互相覆盖）
- 样式优先级混乱（同类名不同定义）
- 布局系统冲突（Tailwind 的 utility 类和 Bootstrap 的组件类互相干扰）
- 页面样式完全错乱

**选择指南**：
- **选 Tailwind**：适合自定义设计、需要精细控制、现代开发方式
- **选 Bootstrap**：适合快速原型、需要现成组件、传统开发方式
- **都不选**：纯手写CSS + 本文档的CSS变量系统，最可控

```html
<!-- ⚠️ 只能选择以下一个框架！ -->

<!-- 选项A：Tailwind CSS（推荐用于自定义设计） -->
<script src="https://cdn.tailwindcss.com"></script>

<!-- 选项B：Bootstrap 5（推荐用于快速原型） -->
<link href="https://cdnjs.cloudflare.com/ajax/libs/bootstrap/5.3.0/css/bootstrap.min.css" rel="stylesheet">
<script src="https://cdnjs.cloudflare.com/ajax/libs/bootstrap/5.3.0/js/bootstrap.bundle.min.js"></script>

<!-- 选项C：不使用框架，纯手写CSS（最可控，推荐配合本文档的CSS变量系统） -->
<!-- 不加载任何框架CDN，只使用 css/main.css -->
```

**使用框架时的注意事项**：
- 如果使用 Tailwind：自定义CSS文件中不要重复定义 Tailwind 已有的 utility 类
- 如果使用 Bootstrap：自定义CSS文件必须在 Bootstrap CSS 之后加载，用更高优先级覆盖
- 如果纯手写CSS：必须包含本文档的 CSS Reset 和 CSS 变量系统

## 配色系统

### 色彩对比度强制规范（WCAG 2.1 AA 标准）

**核心原则**：文字与背景的对比度必须达到最低 4.5:1（正常文字）或 3:1（大文字 18px+）

### 禁止使用
- ❌ 灰色背景配深灰/黑色文字（如 #E5E5E5 背景配 #333333 文字，对比度仅 2.8:1）
- ❌ 浅色背景配浅色文字（如 #F5F5F5 背景配 #CCCCCC 文字）
- ❌ 深色背景配深色文字（如 #333333 背景配 #666666 文字）
- ❌ 纯黑 #000000 配纯白 #FFFFFF（对比度过高导致视觉疲劳）
- ❌ 随机RGB颜色，没有经过对比度检测
- ❌ 默认蓝色链接（#0000EE）在白色背景上对比度不足
- ❌ 过于饱和的强调色

### 对比度检测方法
使用在线工具检测配色对比度：
- https://webaim.org/resources/contrastchecker/
- https://contrast-ratio.com/

### 推荐的文字与背景配色组合

**浅色主题（背景 → 文字）**：
| 背景色 | 文字色 | 对比度 | 状态 |
|--------|--------|--------|------|
| #FFFFFF | #1A1A1A | 16.1:1 | ✅ 优秀 |
| #FAFAFA | #1F2937 | 14.5:1 | ✅ 优秀 |
| #F8F9FA | #212529 | 14.2:1 | ✅ 优秀 |
| #F3F4F6 | #374151 | 10.4:1 | ✅ 优秀 |
| #FEF3C7 | #92400E | 5.7:1  | ✅ 通过 |
| #DBEAFE | #1E40AF | 7.2:1  | ✅ 优秀 |
| #E5E5E5 | #1F2937 | 11.8:1 | ✅ 优秀 |

**深色主题（背景 → 文字）**：
| 背景色 | 文字色 | 对比度 | 状态 |
|--------|--------|--------|------|
| #0A0A0A | #FAFAFA | 18.4:1 | ✅ 优秀 |
| #111827 | #F9FAFB | 15.7:1 | ✅ 优秀 |
| #1F2937 | #F3F4F6 | 12.6:1 | ✅ 优秀 |

**❌ 常见错误配色（对比度不足）**：
| 背景色 | 文字色 | 对比度 | 问题 |
|--------|--------|--------|------|

| #333333 | #555555 | 2.1:1 | ❌ 深色主题常见错误 |

## 字体系统

### 禁止作为主字体
Arial, Roboto, Inter, Open Sans, Lato, System UI — 这些字体过于常见，缺乏设计感。但可以作为 `font-family` 的回退字体（fallback）。

**正确写法**：`font-family: 'DM Sans', 'Noto Sans SC', sans-serif;`（主字体有个性，回退用系统字体）

### 推荐的字体组合

| 风格 | 标题字体 | 正文字体 | 回退字体 | 场景 |
|------|---------|---------|---------|------|
| 现代科技 | Syne, DM Sans, Manrope | DM Sans, Manrope | sans-serif | AI产品、开发者工具 |
| 优雅衬线 | Playfair Display, Cormorant Garamond | Lora, Merriweather | serif | 奢侈品、杂志 |
| 粗壮有力 | Oswald, Bebas Neue, Anton | DM Sans, Manrope | sans-serif | 运动品牌、媒体 |
| 极简专业 | Geist, Geist Mono | DM Sans, Manrope | sans-serif | 开发者平台、Vercel |
| 中文现代 | Noto Sans SC, Source Han Sans | Noto Sans SC | sans-serif | 中文网站 |

### 字体CDN示例

## 设计禁忌（Do's and Don'ts）

### ✅ 应该做
- 使用CSS变量定义设计系统
- 保持视觉层次清晰
- 一致的间距和圆角
- 深色主题使用合适的对比度
- 使用微动画提升体验

### ❌ 不应该做
- 使用纯黑背景配纯白文字
- 使用默认蓝色作为链接色
- 所有元素都有阴影
- 过度使用渐变
- 不一致的圆角大小

## ⚠️ 交付前强制自检流程（必须执行，不可跳过！）

**在向用户报告"完成"之前，必须按以下3个阶段逐一自检。任何一项未通过都必须立即修复后重新检查！**

### 阶段1：文件完整性检查（创建文件后立即执行）

```bash
# 1. 列出项目目录所有文件
ls -laR /mnt/user-data/outputs/project/

# 2. 从HTML中提取所有引用的CSS/JS/图片文件
grep -oE 'href="[^"]*\.css"' /mnt/user-data/outputs/project/index.html
grep -oE 'src="[^"]*\.js"' /mnt/user-data/outputs/project/index.html
grep -oE 'src="[^"]*\.(jpg|png|svg|webp)"' /mnt/user-data/outputs/project/index.html

# 3. 逐个确认被引用的文件存在
```

**必须通过的检查项**：
- [ ] HTML中引用的每个CSS文件都实际存在且非空
- [ ] HTML中引用的每个JS文件都实际存在且非空
- [ ] HTML中引用的每个图片文件都实际存在
- [ ] CSS中 `@import` 或 `url()` 引用的资源都存在
- [ ] 所有文件使用相对路径（无 `file://`、无绝对路径）
- [ ] 导航链接指向的HTML文件都已创建
- [ ] 多页应用：CSS/JS已分离到独立文件（非内联）

**如果检查失败**：立即创建缺失文件，修复路径错误，然后重新执行阶段1。

### 阶段2：HTML/CSS基础结构检查

**必须通过的检查项**：
- [ ] 每个HTML文件都有 `<!DOCTYPE html>`（无DOCTYPE = 怪异模式 = 布局错乱）
- [ ] 每个HTML文件都有 `<meta charset="UTF-8">`（无charset = 中文乱码）
- [ ] 每个HTML文件都有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`（无viewport = 手机端缩放异常）
- [ ] 每个CSS文件开头都有CSS Reset（`box-sizing: border-box`、margin/padding归零）
- [ ] 每个CSS文件都定义了 `:root` CSS变量（组件依赖变量，未定义则样式静默失败）
- [ ] 没有同时加载Tailwind和Bootstrap（两者冲突会导致样式错乱）
- [ ] 自定义CSS在框架CSS之后加载（确保优先级正确）
- [ ] JS文件放在 `</body>` 之前（避免阻塞渲染）

**如果检查失败**：立即修复HTML结构或CSS文件，然后重新执行阶段2。

### 阶段3：样式与功能验证

**必须通过的检查项**：
- [ ] 文字与背景色对比度达到4.5:1以上（WCAG 2.1 AA标准）
- [ ] 没有灰色背景配深灰文字的低对比度组合
- [ ] 响应式布局在移动端（<768px）正常显示
- [ ] 所有按钮和链接可点击且有hover效果
- [ ] 表单输入框可聚焦且有focus样式
- [ ] 图片有 `alt` 属性
- [ ] 外部链接使用 `target="_blank" rel="noopener noreferrer"`
- [ ] 没有空 `href=""` 或无意义 `href="#"` 的链接
- [ ] 浏览器控制台无JavaScript错误
- [ ] 页面在Chrome/Firefox/Safari下显示正常

**如果检查失败**：立即修复样式或功能问题，然后重新执行阶段3。

完成所有3个阶段后，必须输出自检报告：

```

### 阶段1：文件完整性
```

## 常见问题排查

### 问题：outputs 目录只有 index.html

**原因1：AI 创建了 CSS/JS 但没有写入文件**
- 错误做法：在 HTML 中写了 `<link rel="stylesheet" href="css/style.css">` 但没有实际创建 css/style.css 文件
- 解决：必须显式创建每个文件

**原因2：AI 把样式和脚本内联到 HTML**
- 错误做法：把所有 CSS 放在 `<style>` 标签内，所有 JS 放在 `<script>` 标签内
- 解决：分离到独立文件并正确引用

**原因3：文件路径错误**
- 错误做法：创建了文件但路径不匹配
- 解决：确保 `css/main.css` 和 `css/style.css` 等路径正确

### 验证步骤

1. **解析 HTML 引用**：
   ```bash
   # 列出 outputs 目录所有文件
   ls -la /mnt/user-data/outputs/
   
   # 检查 html 中引用的文件是否存在
   grep -E 'href="css/|src="js/|src="images/' index.html
   ```

2. **检查文件数量**：
   - 如果 HTML 有 `<link rel="stylesheet" href="css/xxx.css">`，必须有对应的 css/xxx.css 文件
   - 如果 HTML 有 `<script src="js/xxx.js">`，必须有对应的 js/xxx.js 文件
   - 如果 HTML 有 `<img src="images/xxx.jpg">`，必须有对应的 images/xxx.jpg 文件

3. **使用 Read 工具验证**：
   - 读取 index.html 检查引用路径
   - 逐个确认被引用的文件存在

## 项目类型判断：单页 vs 多页

### 单页应用 (SPA) 适用场景
- 简单展示页面（个人主页、作品集）
- 单一功能页面（登录、注册、表单）
- 营销 Landing Page
- 不需要深层导航的简单网站

### 多页应用适用场景
- 需要多个独立页面（关于我们、服务、联系等）
- 内容丰富的网站（博客、新闻、文档）
- 需要不同布局的页面
- SEO 优化要求高的网站
- 用户需要书签/分享特定页面的需求

### 判断规则

```javascript
// 如果满足以下任一条件，选择多页应用：
const shouldUseMultiPage = (
  userRequest.includes("多个页面") ||
  userRequest.includes("关于") ||
  userRequest.includes("服务") ||
  userRequest.includes("博客") ||
  userRequest.includes("产品列表") ||
  userRequest.includes("详细页") ||
  userRequest.includes("文档") ||
  userRequest.includes("导航到") ||
  pages > 3
);
```

### 多页应用文件结构

```
project/
├── index.html          # 首页/Landing Page
├── about.html          # 关于我们
├── services.html       # 服务介绍
├── contact.html       # 联系我们
├── css/
│   └── main.css      # 共享样式
├── js/
│   └── main.js       # 共享脚本
└── images/           # 图片资源
```

### 单页应用文件结构

```
project/
├── index.html          # 单一入口文件（CSS和JS可内联）
├── images/            # 图片资源（可选）
```

**单页应用允许**：将 CSS 和 JavaScript 直接写在 index.html 中（使用 `<style>` 和 `<script>` 标签）

**多页应用必须**：CSS 和 JS 分离到独立文件，所有页面共享

- 使用相对路径引用本地图片

**优先级 3：使用免费图库 CDN 直链** ⭐

### HTML 中使用图片

```html
<!-- ✅ 优先级 1：直接使用网络图片 URL -->
<img src="https://images.unsplash.com/photo-1522202176988-66273c2fd55f?w=800&q=80" alt="团队协作">

<img src="images/team/photo-1.webp" alt="Team Member">

<img src="file:///Users/xxx/image.jpg">
<img src="/Users/xxx/image.jpg">
<img src="C:\Users\xxx\image.jpg">
<img src="" alt=""> <!-- 空 src -->
```

### CSS 中使用背景图片

```css
/* ✅ 优先级 1：网络图片 URL */
.hero {
  background-image: url('https://images.unsplash.com/photo-xxx?w=1920&q=80');
}

/* ✅ 优先级 2：本地相对路径 */
.hero {
  background-image: url('../images/hero.jpg');
}

/* ✅ 优先级 4：CSS 渐变占位（最后选择） */
.hero {
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
}

/* ❌ 禁止使用 */
.hero {
  background-image: url('file:///Users/xxx/image.jpg');
}
```

### 图片懒加载优化

```html
<!-- 使用 loading="lazy" 优化非首屏图片 -->
<img src="https://images.unsplash.com/photo-xxx?w=800&q=80" alt="描述" loading="lazy">

<!-- 使用 srcset 响应式图片 -->
<img 
  src="https://images.unsplash.com/photo-xxx?w=800&q=80" 
  srcset="
    https://images.unsplash.com/photo-xxx?w=400&q=80 400w,
    https://images.unsplash.com/photo-xxx?w=800&q=80 800w,
    https://images.unsplash.com/photo-xxx?w=1200&q=80 1200w
  "
  sizes="(max-width: 768px) 100vw, 50vw"
  alt="描述"
>
```

## 链接完整性规范

### 链接使用原则

**核心要求**：所有链接必须完整有效，不能出现点击链接打不开或页面不存在的情况

### 内部链接规范

**✅ 正确做法**：
```html
<!-- 使用相对路径链接内部页面 -->
<a href="about.html">关于我们</a>
<a href="contact.html">联系我们</a>
<a href="products/index.html">产品中心</a>

<!-- 使用锚点链接 -->
<a href="#features">查看特性</a>
<a href="#pricing">查看价格</a>

<!-- 使用 JavaScript 处理空链接 -->
<a href="javascript:void(0)" onclick="handleClick()">点击操作</a>
```

**❌ 禁止使用**：
```html
<!-- ❌ 空链接 -->
<a href="">空链接</a>
<a href="#">无意义锚点</a>

<!-- ❌ 不存在的页面 -->
<a href="nonexistent.html">不存在的页面</a>

<!-- ❌ 错误的路径 -->
<a href="../about.html">错误的路径引用</a>
```

### 外部链接规范

**✅ 正确做法**：
```html
<!-- 使用完整的 HTTPS URL -->
<a href="https://github.com/example" target="_blank" rel="noopener noreferrer">GitHub</a>
<a href="https://twitter.com/example" target="_blank" rel="noopener noreferrer">Twitter</a>

<!-- 使用已知有效的 CDN 资源 -->
<link href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/css/all.min.css" rel="stylesheet">
```

**❌ 禁止使用**：
```html
<!-- ❌ HTTP 协议（应使用 HTTPS） -->
<a href="http://example.com">不安全的链接</a>

<!-- ❌ 可能失效的短链接 -->
<a href="https://bit.ly/xxx">短链接</a>

<!-- ❌ 本地开发服务器链接 -->
<a href="http://localhost:3000">本地链接</a>
```

### 链接完整性检查清单

在交付前必须检查：

- [ ] 所有内部链接指向的 HTML 文件已创建
- [ ] 所有外部链接使用 HTTPS 协议
- [ ] 所有外部链接是已知有效的 URL（GitHub、Twitter、知名 CDN 等）
- [ ] 没有空 `href=""` 或无意义 `href="#"` 的链接
- [ ] 外部链接使用 `target="_blank" rel="noopener noreferrer"`
- [ ] 导航栏链接与页面结构一致
- [ ] 页脚链接完整有效
- [ ] 社交媒体链接使用正确的平台 URL

### 常见有效外部链接参考

**社交媒体**：
- GitHub: `https://github.com/username`
- Twitter/X: `https://twitter.com/username` 或 `https://x.com/username`
- LinkedIn: `https://linkedin.com/company/companyname`
- Facebook: `https://facebook.com/pagename`

**CDN 资源**：
- CDNJS: `https://cdnjs.cloudflare.com/ajax/libs/...`
- jsDelivr: `https://cdn.jsdelivr.net/npm/...`
- unpkg: `https://unpkg.com/package@version/...`

**字体服务**：
- Google Fonts 国内镜像: `https://fonts.font.im/...`
- Google Fonts: `https://fonts.googleapis.com/...`
