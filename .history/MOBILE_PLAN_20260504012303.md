# AweeClaw Mobile — 移动端方案设计

> 基于 UniApp + WebSocket 的跨平台移动端方案，适配 iOS / Android / 鸿蒙 / 微信小程序

---

## 一、项目定位

AweeClaw 桌面端是功能完整的 AI 代码编辑器，移动端定位为**轻量级远程伴侣**：

| 维度 | 桌面端 | 移动端 |
|------|--------|--------|
| 核心场景 | 编码、文件操作、终端 | 对话、任务监控、快捷指令 |
| 交互方式 | 键鼠 + 快捷键 | 触屏 + 语音 |
| 在线要求 | 本地为主 | 必须连接桌面端 |
| 数据存储 | 本地文件系统 | 本地缓存 + 远程同步 |

**一句话定义**：移动端是 AweeClaw 桌面端的远程控制面板和随身 AI 助手。

## 二、技术选型

### 2.1 框架：UniApp (Vue 3 + TypeScript)

| 候选方案 | iOS | Android | 鸿蒙 | 微信小程序 | 生态 | 学习成本 |
|----------|-----|---------|------|-----------|------|---------|
| **UniApp** | ✅ | ✅ | ✅ (uni-app x) | ✅ | 成熟 | 低 |
| Taro | ✅ | ✅ | ❌ | ✅ | 成熟 | 中 |
| Flutter | ✅ | ✅ | ⚠️ 实验性 | ❌ | 独立 | 高 |
| React Native | ✅ | ✅ | ❌ | ❌ | 成熟 | 中 |

**选择 UniApp 的理由**：
1. **鸿蒙适配**：uni-app x 基于 uvue 原生渲染，可编译为鸿蒙 NEXT 原生应用
2. **微信小程序**：零成本编译，无需额外适配
3. **Vue 3 + TS**：与桌面端 React 技术栈不同但理念一致，Composition API 思维模型相似
4. **条件编译**：`#ifdef` 语法优雅处理平台差异，不需要维护多套代码
5. **插件市场**：成熟的 uni-ui 组件库和社区插件

### 2.2 通信：WebSocket

```
┌─────────────┐     WebSocket      ┌──────────────────┐
│  Mobile App  │ ◄──────────────► │  AweeClaw Desktop │
│  (UniApp)    │   wss://host:port │  (Electron)       │
└─────────────┘                    └──────────────────┘
```

**为什么选 WebSocket 而非 HTTP 轮询**：
- AI 流式输出需要实时推送（SSE over WS）
- 情感系统状态需要低延迟同步
- IM Channel 消息需要即时触达
- 双向指令（移动端 → 桌面端执行命令）需要持久连接

### 2.3 辅助技术栈

| 类别 | 选型 | 说明 |
|------|------|------|
| 状态管理 | Pinia | Vue 3 官方推荐，轻量高效 |
| UI 组件 | uni-ui + 自定义 | 基础组件用 uni-ui，核心交互自研 |
| 样式方案 | SCSS + rpx | rpx 自适应多端屏幕 |
| 构建工具 | Vite (HBuilderX 内置) | 开发体验好 |
| 代码规范 | ESLint + Prettier | 统一代码风格 |
| 国际化 | vue-i18n | 中英双语 |

### 3.2 WebSocket 通信协议

#### 连接生命周期

```
1. 发现阶段：mDNS / 局域网扫描 / 手动输入 IP
2. 握手阶段：Token 认证 + 能力协商
3. 通信阶段：双向消息流
4. 心跳保活：30s 间隔 ping/pong
5. 断线重连：指数退避 (1s → 2s → 4s → ... → 30s)
```

#### 消息帧格式

```typescript
interface WSFrame {
  id: string
  type: WSMessageType
  payload: unknown
  timestamp: number
  ack?: boolean
}

type WSMessageType =
  | 'auth:request' | 'auth:response'
  | 'chat:message' | 'chat:stream' | 'chat:stream:end'
  | 'task:create' | 'task:update' | 'task:complete'
  | 'channel:message' | 'channel:status'
  | 'emotion:update'
  | 'file:read' | 'file:write'
  | 'command:execute' | 'command:result'
  | 'system:heartbeat' | 'system:ping' | 'system:pong'
  | 'error'
```

#### 核心消息流

**对话流式交互**：
```
Mobile                          Desktop
  │                                │
  │── chat:message ──────────────►│  用户发送消息
  │                                │── LLM 处理
  │◄── chat:stream ──────────────│  流式 token
  │◄── chat:stream ──────────────│  ...
  │◄── chat:stream:end ──────────│  完成
  │                                │
```

**任务执行监控**：
```
Mobile                          Desktop
  │                                │
  │── task:create ───────────────►│  创建任务
  │◄── task:update ──────────────│  进度更新
  │◄── task:update ──────────────│  ...
  │◄── task:complete ────────────│  任务完成
  │                                │
```

**IM Channel 消息**：
```
Desktop                         Mobile
  │                                │
  │── channel:message ───────────►│  IM 消息推送
  │◄── channel:message ──────────│  移动端回复
  │                                │
```

### 3.3 桌面端 WebSocket Server 扩展

需要在 AweeClaw 桌面端新增 WebSocket Server 模块：

```
src/main/services/mobile/
├── MobileWSServer.ts        WebSocket 服务器
├── MobileAuthService.ts     设备认证与 Token 管理
├── MobileMessageHandler.ts  消息路由与分发
├── MobileSyncService.ts     数据同步服务
└── index.ts
```

**认证流程**：
1. 桌面端启动 WS Server，生成配对二维码
2. 移动端扫码获取 Token（同局域网）
3. 后续连接使用 Token 认证
4. 支持多设备同时连接

## 六、平台适配策略

### 6.1 条件编译矩阵

```typescript
// #ifdef APP-PLUS
// iOS / Android 原生能力：推送、生物识别、文件系统
// #endif

// #ifdef MP-WEIXIN
// 微信小程序：订阅消息、小程序码、分享
// #endif

// #ifdef HARMONY
// 鸿蒙 NEXT：鸿蒙推送、系统能力
// #endif
```

### 6.2 各平台差异处理

| 能力 | iOS/Android | 微信小程序 | 鸿蒙 |
|------|-------------|-----------|------|
| WebSocket | uni.connectSocket | uni.connectSocket | uni.connectSocket |
| 本地存储 | uni.setStorage | uni.setStorage | uni.setStorage |
| 推送通知 | uni.push + 厂商通道 | 订阅消息 | 鸿蒙推送 |
| 二维码扫描 | uni.scanCode | uni.scanCode | uni.scanCode |
| 语音识别 | 原生插件 / 第三方 SDK | 微信同声传译 | 鸿蒙 AI 能力 |
| 文件浏览 | 原生文件系统 | 不支持（降级为列表） | 原生文件系统 |
| 生物识别 | uni.startSoterAuthentication | 不支持 | 鸿蒙生物认证 |
| 后台保活 | 原生插件 | 不支持 | 长时任务 |

### 6.3 微信小程序特殊适配

- **包大小**：主包 ≤ 2MB，总包 ≤ 20MB，采用分包加载
- **WebSocket 限制**：同时只能有 1 个 WS 连接
- **无后台运行**：退到后台 WS 断开，重进自动重连
- **无文件系统**：文件浏览功能降级为只读列表
- **分享能力**：利用小程序分享卡片传播

### 6.4 鸿蒙 NEXT 适配

- 使用 **uni-app x** 编译模式（uvue 原生渲染）
- 鸿蒙推送服务 (Push Kit) 集成
- 鸿蒙 AI 语音识别能力
- 长时任务保活 WS 连接
- 鸿蒙安全沙箱适配

## 七、安全设计

### 7.1 传输安全

- **WSS 加密**：TLS 1.3 加密传输
- **Token 认证**：JWT Token，有效期 7 天，自动续期
- **设备绑定**：Token 绑定设备指纹，防止 Token 被盗用

### 7.2 数据安全

- 敏感数据加密存储（uni.setStorage + AES）
- 代码内容不在移动端持久化（仅缓存当前会话）
- 支持远程擦除（桌面端可一键断开并清除移动端数据）

### 7.3 操作安全

- 敏感操作（文件写入、命令执行）需移动端二次确认
- 操作审计日志同步到桌面端
- 速率限制：防止移动端误操作或恶意请求

## 十一、技术风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 微信小程序 WS 限制 | 后台断连 | 退回前台自动重连 + 消息补拉 |
| 鸿蒙 NEXT 生态不成熟 | 组件/插件缺失 | 条件编译降级 + 原生插件补充 |
| 流式渲染性能 | 大量 token 卡顿 | 消息合并 + 虚拟列表 + 增量渲染 |
| 局域网发现 | 跨网段无法连接 | 支持 IP 直连 + 可选云中转 |
| 多设备并发 | 桌面端负载 | 消息广播 + 背压控制 |

## 十二、总结

本方案以 **UniApp + WebSocket** 为核心，构建 AweeClaw 的移动端伴侣应用：

1. **一套代码，四端运行**：iOS / Android / 鸿蒙 / 微信小程序
2. **实时双向通信**：WebSocket 持久连接，流式对话 + 状态同步
3. **情感 IP 陪伴**：复用桌面端情感系统，移动端更亲密的交互
4. **渐进式开发**：MVP 先通对话，逐步叠加任务/Channel/语音
5. **安全可控**：Token 认证 + 设备绑定 + 远程擦除 + 操作审计

移动端不是桌面端的简单移植，而是面向移动场景的**重新设计**——让 AweeClaw 的 AI 能力随时随地在手边。
